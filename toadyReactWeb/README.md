# TOADY 프론트엔드 (`toadyReactWeb`)

React 기반의 청약 일정 캘린더 및 분양 정보 웹 애플리케이션입니다. 월별 청약 일정을 데스크톱·모바일 화면에 맞춰 보여주고 공고 상세, 경쟁률, 위치, 댓글을 제공합니다.

## 주요 기능

- 데스크톱 FullCalendar 월간 일정 및 모바일 일정 캘린더
- 공고 유형·지역·접수 일정 필터링
- 전체 기간 공고 자동완성 검색과 선택한 접수 월로 캘린더 이동
- 공고 상세 정보, 경쟁률·당첨 가점, 위치 지도, 댓글 화면
- TanStack Query를 이용한 서버 데이터 캐싱 및 댓글 변경 후 쿼리 갱신

## 기술 스택

| 구분 | 기술 |
| --- | --- |
| UI | React 18, Material UI 5 |
| 개발 서버·빌드 | Vite 5 |
| 서버 상태 | TanStack Query v5 |
| 일정 화면 | FullCalendar |
| 지도 | Kakao Maps JavaScript SDK |
| 웹 서버 | Nginx, Docker |

## 화면 및 코드 구조

```text
src/
├── api/                      # 공통 Fetch 기반 API 클라이언트
├── config/                   # 개발/프로덕션 API 주소 설정
├── features/
│   ├── announcement/          # 공고 API 함수 및 TanStack Query 훅
│   └── auth/                  # 인증 API 및 사용자 상태
├── components/               # 레이아웃, 날짜 선택, 지도 등 공통 UI
├── views/
│   ├── main/                 # 캘린더 메인 화면
│   │   ├── components/        # 공급유형·지역 필터 및 공고 원문 UI
│   │   ├── hooks/             # 자동완성·검색 옵션·목록 필터링
│   │   ├── calendar/          # 데스크톱 및 모바일 캘린더
│   │   ├── subscriptDetail/   # 공고 상세 화면
│   │   ├── subscriptRate/     # 경쟁률·가점 화면
│   │   └── subscriptComment/  # 댓글 화면
│   ├── login/
│   └── signup/
└── utils/                    # 날짜·문자열·SEO 유틸리티
```

메인 화면은 캘린더 조회와 상세 패널을 연결합니다. `announcementFilters.js`는 지역·유형·검색 옵션을 정의하고, `hooks/useAnnouncementSearch.js`는 자동완성·옵션 조합·목록 필터링을 담당합니다. `components/AnnouncementFilters.jsx`는 필터 UI, `components/AnnouncementNotice.jsx`는 공고 원문과 유형별 상세를 표시합니다.

## 주요 UX 동작

### 반응형 청약 캘린더

화면 크기에 따라 데스크톱에서는 FullCalendar 월간 뷰를, 모바일에서는 별도 모바일 캘린더를 표시합니다. 공고를 선택하면 상세 패널을 열어 상세 정보와 관련 기능을 확인할 수 있습니다.

### 전체 기간 공고 검색

캘린더는 선택 기간의 공고를 모든 페이지에 걸쳐 조회합니다. 명시적으로 `page`를 지정하는 목록 조회는 기존 페이징 방식을 유지합니다.

검색 입력은 2자 이상일 때 300ms 디바운스로 `/api/v1/announcements/suggestions`를 호출합니다. 검색 결과에는 접수 월과 주소 정보를 함께 표시합니다. 과거 공고를 선택하면 `rceptBgnde` 기준 월로 캘린더를 이동하고 해당 공고 상세 화면을 엽니다. 지역·현재 월의 공고 검색 옵션도 같은 입력 UI에서 제공합니다.

### 서버 상태 캐싱

서버 데이터를 컴포넌트 로컬 상태와 분리하고, 동일 조건의 조회 결과를 재사용해 화면 이동 시 불필요한 네트워크 요청을 줄이기 위해 TanStack Query를 사용합니다. 공고 목록 조회의 `staleTime`은 3분이며, 상세·경쟁률 등 다른 조회는 훅별 설정을 사용합니다. 댓글 작성·수정·삭제 후에는 관련 쿼리를 무효화해 최신 데이터를 다시 가져옵니다.

## 인증 토큰 갱신

공통 API 클라이언트는 서버의 `Authorization` 응답 헤더에서 갱신 토큰을 읽어 localStorage와 Zustand에 반영합니다. 로그아웃 또는 다른 계정 로그인 후 도착한 이전 응답은 인증 상태를 복구하거나 초기화하지 않습니다.

## 로컬 실행

필요 환경: Node.js 22, npm. 의존성 잠금 파일은 `package-lock.json`으로 통일합니다.

```bash
cp .env.example .env.local
npm ci
npm run dev
```

Vite 개발 서버는 `http://localhost:3000`에서 실행되며 `/api`와 `/webApi` 요청을 `http://localhost:8081`의 로컬 API 서버로 프록시합니다. 백엔드 API가 실행 중이어야 공고·인증 기능을 사용할 수 있습니다.

```bash
# 회귀 테스트 (Node.js 22)
npm test

# 프로덕션 빌드
npm run build

# 빌드 결과 미리보기
npm run preview
```

## API 및 배포 설정

개발 환경에서는 Vite 프록시를 사용하고, 프로덕션 환경에서는 `src/config/index.js`에 설정된 `https://api.toady.co.kr`를 API 주소로 사용합니다. 별도 API 도메인을 호출하므로 운영 환경의 DNS, TLS, Nginx 라우팅 및 API CORS 허용 Origin 설정이 서로 일치해야 합니다.

지도 기능은 `.env.local`의 `VITE_KAKAO_MAP_KEY`에 본인의 Kakao JavaScript 키를 설정하면 사용할 수 있습니다. `src/config/loadKakaoMaps.js`가 SDK를 로드합니다. 키가 없어도 캘린더 화면과 빌드는 사용할 수 있으며 지도 기능에는 키가 필요합니다.

`VITE_*` 값은 빌드 시 브라우저 번들에 포함됩니다. JavaScript 키는 서버 비밀키가 아니며 Kakao 개발자 콘솔에 허용 도메인을 등록해야 합니다. DB 비밀번호·JWT 비밀키·서버용 API 키는 이곳에 넣지 않습니다.

Docker 빌드 시 `--build-arg VITE_KAKAO_MAP_KEY`로 전달합니다. CI 배포는 GitHub Actions의 `VITE_KAKAO_MAP_KEY` Secret을 사용하며, 누락되면 이미지 생성 전에 중단합니다. 정적 앱이므로 실행 중인 컨테이너의 환경변수만 바꾸어서는 키가 변경되지 않고 다시 빌드해야 합니다.

Dockerfile은 Node.js 이미지에서 Vite 정적 산출물을 만든 뒤 Nginx 이미지에서 서빙하는 멀티스테이지 빌드입니다. `nginx.conf`에는 SPA 라우팅 fallback과 정적 파일 캐시 헤더, Gzip 압축을 설정해 반복 방문 시 리소스 재사용을 돕고 텍스트 기반 에셋의 전송량을 줄이도록 했습니다.

### 인증 요청과 탭 간 상태 동기화

로그인·회원가입·메일 인증·비밀번호 재설정 요청에는 기존 JWT를 첨부하지 않습니다. 화면과 일반 API 요청은 같은 Zustand 인증 상태를 사용하며, 다른 탭의 로그인·로그아웃은 `storage` 이벤트로 동기화합니다. 계정 변경 시 이전 조회를 취소하고 쿼리 데이터를 초기화해 활성 화면을 새 계정으로 다시 조회합니다. 같은 계정의 토큰 갱신은 캐시를 초기화하지 않습니다.

통합 달력의 댓글 수는 서버의 `commentCount`를 사용합니다. 댓글·답글 등록 또는 삭제 후 댓글 목록·상세와 통합 공고 목록 캐시를 무효화해 표시를 갱신합니다.

댓글 전체 조회는 번호 커서를 사용해 새 댓글·삭제에 따른 페이지 경계 이동을 방지하며 공고·계정 변경 시 작성 중 내용도 초기화합니다. 공고·경쟁률·가점·특별공급 조회는 실패와 정상적인 빈 응답을 구분하고 재시도 버튼을 제공합니다. 지도 SDK 초기화와 주소 검색에는 각각 대기 시간 제한이 있고, 새 검색이나 화면 종료 뒤의 이전 콜백은 무시합니다. 로컬 상세 정보도 HTML 직접 삽입 대신 안전한 텍스트/줄바꿈 렌더링을 사용합니다.

### 방문 집계

`PageViewTracker`가 첫 진입 및 pathname 이동을 익명으로 기록합니다. 새로고침은 새 조회, 쿼리·해시 변경과 동일 경로 이동은 추가 조회가 아닙니다. 허용 경로는 `/`, `/login`, `/certify`, `/showSubscriptDetail`이며 모달 내부의 개별 공고 열기·탭 변경은 별도 조회로 세지 않습니다. 이메일 인증 코드 등 URL 쿼리는 전송하지 않습니다.

localStorage의 `toady.analytics.visitor`로 브라우저 방문자를 구분하고 `toady.analytics.session`은 마지막 페이지 조회 후 30분이 지나면 새 세션을 생성합니다. 같은 브라우저의 탭은 식별자를 공유하며 저장소 차단 시 메모리로 대체합니다. 실제 사람 수 또는 사이트 체류 시간을 뜻하지 않습니다. 수집 목적과 보관 정책은 사이트 개인정보 안내에 반영해야 합니다.

전송은 인증 헤더 없이 수행하고, 5초 제한 및 최대 한 번 재시도를 적용합니다. 같은 이벤트 ID를 재사용해 DB 중복 집계를 막습니다. 영구 전송 대기열은 두지 않으므로 오프라인·페이지 종료 중의 이벤트는 유실될 수 있습니다.

### 청약 조사와 나의 청약

`/my`는 관심 공고·다가오는 일정·준비 체크리스트·비공개 메모·최대 3개 비교를 제공합니다. 비회원은 `toady.planner.guest`에 최대 50개를 저장하고 서버의 최신 요약을 조회합니다. 실패 시 저장 당시 요약이라는 안내를 표시합니다. 회원은 JWT 기반 API에 저장하며 계정이 바뀌면 조회 캐시와 편집 카드가 초기화됩니다. 기기 저장 공고 가져오기는 명시적 클릭으로 실행하며 기존 계정 메모는 유지합니다. 일부 가져오기 후 오류가 나면 완료된 항목은 유지되고 다시 실행할 수 있습니다.

공고 상세의 `ResearchPanel`은 접수·발표·공급 규모를 짧게 요약하고 **청약 정보** 탭을 기본으로 엽니다. 자체 일정·사업 정보를 먼저 제공하며 청약홈 원문은 요청할 때 적정 크기 모달로 표시합니다. 삽입을 차단하는 원문을 위해 새 창 열기를 보조로 제공합니다. 상세 탭은 본문 스크롤 영역 밖에 배치해 겹침을 방지합니다. 나의 청약에서는 캘린더 전환 없이 기존 화면 위에 상세를 열어 메모·비교 선택을 유지합니다. 분양가 범위는 상단에서 바로 확인하고 전체 주택형·분양가는 청약 정보 안에서 이어봅니다. **동네 실거래**는 별도 탭에서 조회하고 저장·일정 추가·나의 청약 버튼은 상세 제목 아래에 고정합니다. 동네 실거래 탭에서는 국토교통부 신고 거래를 조회합니다. 같은 법정동·최근 3개월·면적 ±5㎡ 필터를 지원하며 취소 거래를 제외합니다. 기존 카카오 JavaScript SDK로 공고 주소의 법정동을 확인하므로 사용 도메인을 카카오 개발자 콘솔에 등록해야 합니다. 국토부 키는 API 서버의 `MOLIT_TRADE_SERVICE_KEY`로만 설정합니다. 네이버 카페·검색 연동은 사용하지 않습니다. 생활권 별칭은 `/api/v1/living-areas`를 사용합니다. 기기에는 광역지역·검색 선택·보기 방식·최근 본 공고도 저장됩니다. 최근 기록은 화면에서 삭제할 수 있습니다.

나의 청약의 **캘린더 연결**은 회원에게 구독 주소(구글 캘린더 추가·아이폰/맥 webcal·주소 복사)를 제공합니다. 재발급·해지 확인도 같은 창 안에서 처리해 뒤로가기 한 번에 닫힙니다. 비회원이 ‘로그인하고 연결하기’를 누르면 연결 창 자리에 로그인 창을 열고, 로그인 후 연결 창을 다시 엽니다. 로그인을 취소하면 재개하지 않습니다. 생활권 공개 페이지에서 `/?area={slug}&month=YYYY-MM`으로 들어오면 생활권 검색과 해당 월을 한 번 적용하고 주소에서 지워 새로고침·뒤로가기 때 사용자의 이후 검색을 덮어쓰지 않습니다. 페이지뷰는 세션 첫 조회에만 외부 유입 도메인을 함께 보냅니다.

`/score` 가점 계산기는 `features/score`의 규칙표(`scoreRules.js`)로 점수를 계산하고 `toady.myScore`에 저장합니다. 공유 주소(`?h=&d=&a=`)는 받은 사람의 저장값을 덮어쓰지 않습니다. 공고 경쟁률 탭에는 내 가점 비교 카드와 경쟁률 예상 투표(`features/story/RatePoll.jsx`)를, 이야기 탭에는 일정 단계별 질문 칩(말머리 `[주제]`)을 둡니다. 동네 실거래 탭에서 면적을 고르면 같은 면적 공급금액과 실거래 중간값을 나란히 보여줍니다. `/zupzup`·`/weekly`에서 넘어온 `?focus=unranked`, `?month=`는 한 번만 적용하고 주소에서 지웁니다.

웹 푸시는 `features/push`에 있습니다. `public/sw.js`는 알림 표시와 클릭 이동만 처리하고 화면·API를 캐시하지 않습니다. 알림을 누르면 열린 TOADY 창은 새로고침 없이 앱 라우터로 공고 상세(`/?subscriptSeq=`)를 열고, 창이 없으면 새 창을 엽니다. `public/manifest.webmanifest`와 같은 출처 PNG 아이콘(192·512, 애플 터치 180, 알림 배지 96)으로 홈 화면 추가를 지원합니다. 권한은 사용자가 '알림 켜기'를 눌렀을 때만 요청하며, 안내 카드는 닫으면 `toady.push.promptDismissed`로 기억해 다시 보이지 않습니다(나의 청약 › 더보기 › 알림 설정은 계속 사용 가능). 운영 Nginx는 `/sw.js`·`/manifest.webmanifest`를 장기 캐시하지 않습니다.

ICS는 날짜별 종일 일정이며 종료일 다음 날을 DTEND로 지정합니다. UTF-8 75바이트 줄 접기와 텍스트 이스케이프를 적용합니다. 내려받기 시점의 일정 사본으로, 이후 변경은 자동 동기화하지 않습니다.

운영 Nginx는 독립 공고 URL에서 API의 HTML 요약을 제공합니다. 서버 요약에서 전체 기능으로 이동할 수 있고 React 내부 이동에서는 상세 패널을 엽니다. 개발 Vite는 React 경로만 처리하므로 서버 HTML은 API 경로에서 별도 확인합니다. 외부 EC2 Nginx도 `/announcements/`, `/announcement-sitemap.xml`, `/sitemaps/` 요청을 프론트 컨테이너로 전달해야 합니다.

방문 로그에 `/my`와 공고 경로 종류를 추가했습니다. `TB_USAGE_EVENT`에는 공고 상세·관심 저장·알림 선택·외부 조사·공식 공고 이동·비교 행동을 익명으로 수집합니다. URL 전체, 메모, 검색어, 회원 ID는 보내지 않습니다. 공식 페이지 클릭은 신청 완료가 아니며 브라우저 차단·오프라인으로 측정이 누락될 수 있습니다. 수집 목적·보관 정책은 실제 서비스 개인정보 안내에 반영해야 합니다.

### 목록 복귀와 일정 중복 회귀 검증

조회 월·기간은 `browseState`와 Main이 소유하며 달력이 마운트되지 않은 목록 모드에서도 API 요청이 활성화됩니다. 조회 기간은 해당 월 전후의 달력 표시 범위를 포함하고, 월·보기 방식은 메뉴 이동과 새로고침 후 복원합니다. 목록에서도 조회 월을 이동할 수 있습니다.

나의 청약은 공고별 타임라인에서 같은 날짜의 접수 순위·지역을 묶습니다. 상세 접수 일정이 있는 날에는 일반 접수 시작/마감을 반복하지 않습니다. 준비 노트는 펼쳐서 편집하며, 저장하지 않은 변경사항과 저장 완료 상태를 구분합니다. 캘린더 내려받기에도 같은 중복 정리 기준을 적용합니다.

`npm test`에 포함된 `planner-navigation.test.mjs`는 JSDOM에서 실제 App·라우터·Query·화면을 마운트하고 API 응답만 대체합니다. 목록 모드 첫 진입, 목록 → 나의 청약 → 청약캘린더, 월 변경, 달력/목록 전환, 새로고침에 해당하는 재마운트, 노트 저장, 비교 열기/닫기를 검증합니다. `planner.test.mjs`는 접수·특별공급·순위별 지역·발표·계약 일정의 중복 정리와 윤년·연도 경계 조회 기간을 검증합니다. 실제 브라우저 배치와 모바일 화면은 이 DOM 테스트와 별도로 확인합니다.

### 공고 공유 미리보기

공유 버튼은 현재 상세·경쟁률·위치·댓글 탭을 `tabType`에 보존한 공개 공고 URL을 복사합니다. 서버가 공고명·일정·선택 탭에 맞는 Open Graph/Twitter 메타태그와 1200×630 PNG를 제공합니다. 카카오톡에 예전 미리보기가 남으면 카카오 개발자 도구의 공유 디버거에서 해당 URL 캐시를 초기화하세요. 로컬에서는 실제 카카오톡 미리보기를 수집할 수 없으므로 공개 도메인으로 배포한 후 확인해야 합니다.

지도와 실거래는 `useAnnouncementLocation`의 공통 판정을 사용합니다. 정확한 지번·도로명과 시군구가 일치하는 주소 결과를 사용하며, 단지명 검색 후보는 사용자 요청 때만 확인 전 후보로 표시합니다. 행정구역 중심·역·견본주택으로 자동 대체하지 않습니다. 수동 검색은 지도에서만 적용하고 실거래 법정동을 변경하지 않습니다. 상세 하단의 외부 지도·원문 링크 줄은 제거했습니다.

공고별 수동 도면 등록·공식 사이트별 고정 URL 매핑은 사용하지 않습니다. 도면 표시는 공통 데이터 공급 경로를 확보하기 전까지 제공하지 않습니다.

### 시나리오 기반 사용성 검증

공고 탐색 → 필터 결과 없음/초기화 → 상세 → 관심 저장 → 준비 노트 저장 → 상세 왕복 → 비교 → 달력·목록 전환과 재접속을 검증합니다. 모바일 경쟁률·특별공급은 카드로 표시하고, 큰 표는 키보드와 가로 스크롤로 확인할 수 있습니다. 신규 방문자는 달력으로 시작하며 사용자가 선택한 보기는 재접속 시 유지합니다. 메뉴의 청약캘린더를 누르면 저장된 보기와 관계없이 달력으로 이동합니다. 최근 본 공고는 접기/펼치기와 별도 가로 스크롤 영역으로 제한하고 공통 레이아웃에 `min-width: 0`을 적용해 페이지 전체의 가로 밀림을 방지합니다. 실제 사용자 모집 실험과는 별개로 브라우저 시나리오 검증과 App 통합 회귀 테스트를 수행합니다.

상세는 URL과 브라우저 히스토리를 함께 변경합니다. 공유 상세로 직접 진입한 경우에도 첫 뒤로가기는 공고 화면으로 돌아옵니다. 원문·계정·모바일 메뉴 등 팝업은 히스토리에 한 단계씩 쌓아 뒤로가기로 최상위 팝업만 닫고 앞으로가기로 복원합니다.

청약 정보 상단의 모집공고문 PDF는 청약홈 상세에 공개된 첨부 파일로 직접 연결됩니다. 링크가 확인된 경우에만 다운로드 버튼을 표시하며, 파일이 없거나 확인에 실패하면 원문 확인 안내를 제공합니다.

상세의 청약정보 이미지 저장과 경쟁률·가점 이미지 저장은 표 데이터를 PNG로 정리합니다. 긴 표는 행을 생략하지 않고 여러 장으로 나누며, 미리보기에서 표·페이지를 선택해 저장합니다. 공고명·출처·저장일·공고 URL을 각 이미지에 표시하고 비공개 메모 등 개인 정보는 포함하지 않습니다.

지역·단지·생활권 검색은 선택 종류와 검색 필드를 함께 저장하며 기존 문자열 설정도 복원합니다. 모바일 달력은 검색 결과에 일정이 있는 날짜를 자동 선택하고, 유효한 사용자 날짜 선택은 유지합니다. 해당 월에 결과가 없으면 검색 조건 초기화 안내를 제공합니다. 파주 검색 → 나의 청약 → 청약캘린더 복귀 흐름을 통합 테스트에 포함합니다.
